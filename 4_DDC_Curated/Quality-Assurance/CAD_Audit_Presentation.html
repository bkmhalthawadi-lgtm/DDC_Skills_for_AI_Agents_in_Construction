Finding 01 · External References
Broken XREF Paths — All Floor Levels
01
Mistake Identified
XREFs link to a hard-coded UNC network path:
\\server\...\MEP ENGINEERING 15.04.13\XREF\

Two critical problems:

(a) The path timestamp 15.04.13 indicates these XREFs were last confirmed in April 2013 — over 10 years old. Linked files may be superseded revisions.

(b) Absolute drive-letter paths (K:\, d:\D1) break on any machine other than the original workstation.
How to Fix in AutoCAD
  1. 1
    Open the External References palette: type XREF or press Ctrl+7
  2. 2
    Right-click each XREF → Change Path → select Relative Path (project-root-relative)
  3. 3
    Use ETRANSMIT to bundle the host file + all XREFs into a self-contained transmittal package — auto-corrects all paths
  4. 4
    Cross-check each XREF against the current project document register to confirm correct issued revision
  5. 5
    Unload / detach all XREF entries that reference pre-2020 folder paths

Finding 02 · Legacy Object Classes
AEC Proxy Objects — Invisible in Standard AutoCAD
02
Mistake Identified
The file contains AecArchBase80 objects — AutoCAD Architecture 2007 proxy entities. These represent architectural elements: walls, slabs, doors, windows, stairs.

On standard AutoCAD 2023 (without the Architecture extension), these display as empty bounding-box placeholders. Users see a "proxy object" warning on opening, and all architecture background geometry disappears.

This makes the coordination background completely unusable for clash detection — MEP services have no reference geometry to check against.

⚠️ This affects all floor plan levels where an architectural XREF or background layer exists.
How to Fix in AutoCAD
  1. 1
    Open the drawing in AutoCAD Architecture (any version ≥ 2007) — not standard AutoCAD
  2. 2
    Select all AEC objects → run AECEXPLODETOSOLID or EXPLODE to convert to standard polylines, lines, and hatches
  3. 3
    File → Export → AutoCAD DWG with "Explode AEC Objects" option checked — re-save as a plain DWG
  4. 4
    Interim fix: type PROXYGRAPHICS → set to 1 to store visual proxies (shapes display but remain non-editable)

Findings 03, 04 & 05
Geometry · Fonts · Hatch Standards
03–05
03
Mixed 2D/3D Geometry
Flagged
Mistake
Modelspace contains 3D elements (MemberElevationDesign, AecSpaceTriangleD, Spot Elevations) mixed with 2D plan geometry. This makes clash detection unreliable — 3D elements at inconsistent Z-heights create false clearances or missed clashes.
Fix
Record all elevation values in TEXT/MTEXT annotation first
Run FLATTEN command to reduce all geometry to Z=0
Move 3D elements to a dedicated 3D-COORD layer, frozen in 2D viewports
04
Missing Commercial Font
Flagged
Mistake
Drawing uses A_Swis721 Cn BT (Bitstream Swiss 721 Condensed — a paid commercial font). On machines without it, AutoCAD substitutes a default font, causing text overflow into dimension strings and unreadable annotation notes.
Fix
Format → Text Style → replace Swis721 with Arial Narrow or ROMANS.shx
Run REGEN / REGENALL to rebuild display
Include font in ETRANSMIT packages for all recipients
05
ANSI Hatches on ISO Project
Flagged
Mistake
ANSI31 (US steel hatch) and ANSI37 (US brass hatch) used on an ISO metric project. Non-compliant with BS/ISO drawing standards. ANSI37 (brass) may also be applied to wrong materials — likely masonry or insulation.
Fix
QSELECT → Hatch → Pattern Name = ANSI31 → replace with LINE (ISO general section)
Investigate ANSI37 intent: replace with INSUL / AR-CONC / STEEL as appropriate
Add hatch legend to the drawing title sheet

Findings 06, 07 & 08
Elevation Ambiguity · Title Block · File Size
06–08
06
FFL/SSL Conflated in Spot Elevation
Flagged
Mistake
Annotation −0.468 FFL/SSL combines Finished Floor Level and Structural Slab Level in one value. These are typically separated by 75–150 mm of screed and finishes. MEP services coordinated to "FFL" vs "SSL" will be set out at the wrong height, causing penetration and clash errors.
Fix
Confirm SSL from structural drawings / Revit model
Confirm FFL from architectural finishes schedule
Replace with two separate labels: SSL = −0.xxx and FFL = −0.xxx
Update all BOP and drainage invert levels to explicitly reference SSL or FFL
07
Architectural Title Block on MEP Document
Flagged
Mistake
Title block is A1-New Title Sheet from the ARCHCORP-AR (architectural) library. An MEP coordination document requires MEP-specific fields: responsible MEP engineer, discipline code, coordination status stamp, and revision cloud tracking.
Fix
Open block editor (BEDIT) → swap for MEP consultant's approved title block
Fill: Project No. (P159), Discipline (MEP/Building Services), Status ("ISSUED FOR COORDINATION")
Add REVCLOUD with delta markers at each coordination clash location
08
Oversized File / Embedded Raster Images
Flagged
Mistake
At 18.6 MB, the file is 3–4× the expected size for a 2D A0 coordination drawing. Binary analysis confirms embedded PNG raster images. These cause slow viewport regeneration, crashes on workstations with <8 GB RAM, and bloat transmittal packages.
Fix
IMAGE command → locate rasters → Detach; re-attach as external references
Run PURGE (All) then AUDIT (Fix = Y)
Target file size < 5 MB for a 2D A0 coordination sheet

09
🟡 Flagged
Orphaned Dynamic Block History
Mistake Identified
The file contains ACAD_ENHANCEDBLOCKHISTORY and AcDbDynamicBlockRoundTripPurgePreventer records — ghost-history entries created when dynamic blocks are round-tripped between AutoCAD and Revit exports.

These resist standard PURGE and inflate the file database. In rare cases they trigger corruption warnings on open.
How to Fix
  1. 1
    Run PURGE with "Purge Nested Items" enabled — repeat 3–4 times
  2. 2
    If records persist: WBLOCK → * (entire drawing to new file) — strips all orphaned database entries
  3. 3
    Run AUDIT on the new file → Y to fix all reported errors

GCE-* Block Naming Convention
Observation
The GCE- prefixed block library follows a structured, consistent naming convention using discipline prefix codes:

GCE-AT-

GCE-PX-

GCE-DT-

Recommendation: Verify each block's ATTDEF attribute data is populated for downstream equipment schedule extraction and O&M manuals.
